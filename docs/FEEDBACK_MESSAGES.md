## 一、锁座阶段（`select_time_and_wait`）

> 代码位置：`logic/booker.py` `select_time_and_wait()`
> 点击座位后，程序通过两条并行路径检测失败信号：

### 检测机制

| 路径 | 时机 | 方式 | 速度 |
|------|------|------|------|
| 闪电检测 | 点击后立即 | 扫描 `page_source` 关键词 | 极快（不等 UI 渲染） |
| 轮询检测 | 3 秒内每 0.1s | 调用 `_get_latest_ui_message()` 读 toast | 稍慢（等 toast 出现） |

`_get_latest_ui_message()` 优先读 Element UI 组件（`.el-message__content` 等），兜底扫 `page_source`。

### 关键词 → 显示文案映射（`_kw_display`）

| 原始关键词 | 日志中显示的文案 |
|-----------|----------------|
| `不可用` | `该座位不可用，请选择其他座位` |
| `没有可用时间` | `当前的座位已经没有可用时间啦` |
| 其他关键词 | 原样显示（约满、不可预约、已被 等） |

### 全部退出路径

| 路径 | 触发条件 | 日志格式 | 程序行为 |
|------|---------|---------|---------|
| A | 座位元素找不到或点击异常 | `座位 X 在当前自习室找不到或不可点击` | 换下一个座位 |
| B | 闪电检测：`page_source` 含关键词 | `座位 X 被系统拒绝：{display_msg}` | 换下一个座位 |
| C | 轮询检测：toast 含关键词 | `座位 X 被系统拒绝：{display_msg}` | 换下一个座位 |
| D | 3 秒内弹窗未出现，有 toast | `座位 X 点击后未弹出预约框，最后提示：{msg}` | 换下一个座位 |
| E | 3 秒内弹窗未出现，无 toast | `座位 X 点击后未弹出预约框且无任何提示` | 换下一个座位 |
| F | 开始时间标签不可选（1.5s 超时） | `座位 X 的【开始时间 T】不存在/不可选` | 关弹窗，换下一个座位 |
| G | 结束时间标签不可选（1.5s 超时） | `座位 X 的【结束时间 T】不存在/不可选` | 关弹窗，换下一个座位 |
| H | 两个时间都选中成功 | `座位 X (T1-T2) 锁定成功！等待开火...` | 进入提交阶段 |
| I | 未捕获异常 | `座位 X 选座过程发生异常: {e}` | 关弹窗，换下一个座位 |

### 扫描的全部关键词（10 个）

```
没有可用时间  没有可约时间  约满  不可预约  当前不可用
无法预约  已满  已被  不可用  没有可用
```

## 二、提交验证码后

### 阶段 A：验证码确认（`_wait_captcha_result`，2 秒轮询）

> 检测方式：`el-message` toast 优先 → `page_source` 兜底（每 0.5s 扫一次）
> 代码位置：`logic/booker.py` `_wait_captcha_result()`

**这些消息在此阶段就会被拦截，不会走到后面的 `check_result`。**

| 反馈消息 | 命中关键词 | 分类 | 程序行为 |
|---------|-----------|------|---------|
| `验证码错误,请重试` | `验证码错误` | fast_fail | 刷新验证码重试（同座位最多 10 次） |
| `系统繁忙，请稍后:01` | `系统繁忙` / `请稍后` | fast_fail | 刷新验证码重试 |

### 阶段 B：预约结果检查（`check_result`，3 秒 WebDriverWait）

> 检测方式：`el-message` / `el-message-box` / `el-notification` 优先 → `page_source` 兜底
> 代码位置：`logic/booker.py` `_classify_booking_result()` + `check_result()`

#### stop（账号立即停止）

| 反馈消息 | 命中逻辑 | 程序行为 |
|---------|---------|---------|
| `教室仅对部分读者开放` | `"部分读者"` in text | **账号停止** |
| `对不起，您已被加入黑名单，预约权限将在xxxx年xx月xx日恢复。原因：7天内迟到违约，超过3次，加入黑名单7天` | `_is_blacklist_feedback()` 正则匹配 | **账号停止（黑名单）** |
| `已有1个有效预约，请在使用结束后再次进行选择` | `"有效预约"` + `"已有"` | **账号停止** |
| `预约次数已达到每日限制` | `"每日限制"` | **账号停止** |

#### next（换下一个座位）

| 反馈消息 | 命中逻辑 | 程序行为 |
|---------|---------|---------|
| `座位已被他人预约` | `"已被他人预约"` | 换下一个座位 |
| `预约失败，请尽快选择其他时段或座位` | `"预约失败"` | 换下一个座位 |

#### success（抢座成功）

| 反馈消息 | 命中逻辑 | 程序行为 |
|---------|---------|---------|
| `预约成功！` | `"预约成功"` | **发送邮件通知，停止** |

## 三、`_classify_booking_result` 分类决策树

```
输入: result_text
│
├─ _is_stop_booking_feedback()        → "系统可预约时间"+"06:30"+"22:30"  → "stop"
│
├─ "预约成功" in text                  → "success"
├─ "有效预约" + ("已有"/"请在使用结束后") → "stop"
├─ "有效预约" (其他)                    → "success"
├─ "每日限制"                           → "stop"
├─ "部分读者"                           → "stop"
│
├─ _is_blacklist_feedback() 正则匹配   → "blacklist"
│
├─ "验证码错误"/"系统繁忙"/"请稍后"       ┐
│   "请重试"/"操作过于频繁"              ┘  → "retry_captcha"
│
├─ "已被他人预约"                       → "failed"
├─ "已有预约"/"预约失败"                → "failed"
│
└─ 其他                                → "failed"
```

## 四、main.py 日志映射

> `main.py` 消费 booker 的结果后，输出以下日志：

| 场景 | 日志格式 |
|------|---------|
| 锁座失败 | `🔄 [账号] 座位 X 锁定失败，换下一个座位。` |
| 提交触发失败 | `⚠️ [账号] 座位 X 触发提交失败，关闭弹窗换下一个座位。` |
| 系统可预约时间限制 | `🛑 [账号] 收到系统可预约时间限制提示，立即停止抢座: {msg}` |
| 黑名单 | `🛑 [账号] 账号已被加入黑名单！立刻停止抢座: {msg}` |
| 抢座成功 | `🎉🎉🎉 [账号] 座位 X 抢座成功！` |
| 可重试反馈 | `⚠️ [账号] 第 N 次收到可重试反馈【{msg}】，准备继续当前座位。` |
| 提交后被拒绝 | `💔 [账号] 座位 X 提交后被拒绝，换下一个座位。` |
| 验证码重试耗尽 | `💔 [账号] 座位 X 在 N 次重试后仍未通过验证码，换下一个座位。` |
| 全部座位用完 | `❌ [账号] 全部 N 个座位都已尝试，停止当前会话。` |
